# KGE-Unlock

用于酷狗音乐（实际测试使用酷狗免费版）产生的KGE文件解密工具。输入一个 `.kge` 文件，程序尝试自动恢复密钥、解密文件并验证 MP3 / Ogg Vorbis / Ogg Opus / FLAC 音频结构，从标签恢复歌曲名称。

## 文件构成

| 文件 | 作用 |

| `main.py` | 命令行总入口：参数、总流程、打印错误信息。 |
| `decryptor.py` | 单文件解密流程：读取 KGE、调用恢复模块、按块解密、完整性验证、安全输出。 |
| `key_recovery.py` | 密钥恢复策略选择（Ogg、零填充、统计恢复）及 KGE 模板校验。 |

### 依赖与运行环境： Python 3.8 及以上
## 如何使用：
在发布包解压后的目录打开终端执行：

```powershell
python main.py ".kge文件地址"
```

**成功时打印：** 272 字节密钥 A、16 字节密钥 B（均为十六进制）、KGE 加密类型、真实音频格式、输入文件音质、歌曲名、歌手、专辑、输出文件名与路径。解密文件将会保存到输入 KGE 的相同目录，扩展名依据实际音频编码而非缓存音质推断；例如 `康子奇 - 语风 [MQ].mp3`、`双笙 (陈元汐) - 太初 [HQ].ogg`。

**失败时打印：** 完整错误日志和 Python 堆栈，返回非零状态；清理临时文件，不写出伪装为成功的音频。同名输出已存在时拒绝覆盖。

## KGE 解密原理

1. **容器头部：** 校验 KGE 魔数和 1024 字节文件头，取 Native 加密类型 `2/3/4`、已加密的校验模板、16 字节 B (`salt`)。密文音频从头部之后开始计数。
2. **Native 字节映射：** 定义 `M(x) = x XOR ((x & 0x0F) << 4)`；`F(i)` 为 32 位字节偏移的四字节异或折叠。令 `A` 为 272 字节循环密钥，`B` 为 16 字节值：

   ```text
   Type 2: P[i] = M(C[i]) XOR A[i % 272]
   Type 3: P[i] = M(C[i] XOR B[i % 16]) XOR A[i % 272] XOR F(i)
   Type 4: P[i] = M(C[i] XOR B[(i // 272) % 16]) XOR A[i % 272] XOR F(i)
   ```

3. **循环密钥结构：** 已验证格式中，`A[i] = U[i % 17] XOR V[i % 16]`，循环周期 272。文件头的已知模板约束密钥 A 的前 16 字节。
4. **独立恢复路径：** 先利用 Vorbis/Opus 文件头和 Ogg CRC 求解，再检测 MP3/FLAC 零填充区；两者均不适用时，使用 272 个位置的字节统计和 Walsh–Hadamard 变换，对 17 变量异或约束进行全局优化，取得候选密钥。每个候选都需通过 KGE 头部一致性校验。
5. **完整验证及输出：** 解密媒体逐页/逐帧验证：Ogg CRC、MP3 MPEG Layer III 连续帧、FLAC 帧头 CRC-8 和音频帧 CRC-16。验证成功后读取 `TITLE/ARTIST/ALBUM`，按 `歌手 - 歌曲名 [音质].扩展名` 输出；缺失标签时使用源文件名回退。最后原子替换临时文件为目标文件名。

## 注意事项

- 支持 MP3、OGG（Vorbis/Opus）、FLAC，**并不表示每个 KGE 都能自动恢复密钥**：过短、损坏、使用不同循环密钥构造的文件仍可能无法解密。
- 不支持 KGM/KGG/MGG/MFLAC 等其他封装；
